Today's patterns

Click a pattern to jump directly to it in the full sheet.

Daily minimum

  • 20 min: recall old patterns.
  • 45 min: learn today's pattern.
  • 60–90 min: solve representative questions.
  • 15 min: write mistakes and re-solve one problem.

Non-negotiable

  • Try before reading a solution.
  • After a solution, close it and code again.
  • Always ask: “Why this pattern?”
  • Every Sunday-style session: solve mixed problems without topic hints.

Days 1–60 · First pass

  • Follow the sheet's pattern order.
  • Usually study 1–2 patterns per day.
  • Do not chase completion percentage.
  • Move on once you can recognize and implement the core idea.

Days 61–90 · Interview mode

  • Days 61–75: systematic revision.
  • Days 76–84: mixed unseen problems.
  • Days 85–90: timed mock interviews.
  • Spend more time fixing repeated mistakes than collecting new problems.

01 · RECOGNIZE

Find the signal

Read the problem and identify clues that point to the pattern before thinking about code.

02 · EXPLAIN

Say the idea aloud

Explain the approach in 2–3 sentences without looking at code. If you cannot, keep learning.

03 · TEMPLATE

Write from memory

Know the reusable skeleton, not just one solution. Understand what changes between problems.

04 · SOLVE

Attempt before help

Easy: ~20 min. Medium: ~30–40 min. Hard: use it to learn a variation; do not get trapped for hours.

05 · RECALL

Come back later

Use the 1–3–7–14–30 day recall cycle. Re-solve failed problems without notes.

Mastery test

  • Green: recognize + explain + implement + solve Medium.
  • Yellow: recognize but implementation is shaky.
  • Red: cannot recognize or repeatedly fail.
  • Red patterns return every 2–3 days; yellow every 5–7 days.

Revision cycle

  • Day 1: learn.
  • Day 3: recall template.
  • Day 7: solve one without notes.
  • Day 14: solve a random variation.
  • Day 30: explain from memory.

Most important shift

First pass: Pattern → Problem.   Third phase: Problem → Pattern → Solution.

Interviews give you the problem, not the topic. The final 30 days therefore deliberately remove topic hints.

My DSA Mistake Log

Write recurring mistakes here. Keep it short: what you missed, why you missed it, and what signal you should notice next time.

How to use the log

Every failed problem should produce one lesson. Do not copy the solution into the log. Record the reason for failure: wrong pattern, wrong invariant, edge case, implementation error, complexity issue, or forgot a data structure.

Before moving on

  • Can I explain the failure?
  • Can I re-code the solution without looking?
  • Would I recognize the same trap tomorrow?
